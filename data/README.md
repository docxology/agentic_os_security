# data/

Claim registrations for **agentic_os_security** — a private deep review + prospectus of agentic security and operating systems (OpSec, cognitive security, agentic cyber security).

## Contents

- `claim_ledger.yaml` — the single registry of numeric claims used across the manuscript, figures, and reports. Each claim records: `claim_id`, `kind` (`number`), `value`, `source`, `source_tier` (`project_source | generated_metric | manuscript_claim | official_source`), `freshness` (`active`), and `artifact_path` (the backing artifact). The ledger is how every number in the manuscript traces to a code constant, a computed artifact, or a documented official source — no fabricated numbers, no unregistered prose figures.

## Why it exists

The manuscript's claim chain must be auditable: registry constants and pipeline outputs are generated, but prose asserts numbers. The ledger ties those assertions to their backing evidence and keeps the attribution discipline (analytical judgments from documented designs; no penetration-testing claims; no numeric security scores) enforceable in review.

Schema details and editing rules: `AGENTS.md`. Generated datasets live in `output/data/` (disposable, regenerated by `uv run python scripts/10_evaluation_analysis.py`), not here.
