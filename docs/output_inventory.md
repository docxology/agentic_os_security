Cover figure: `graphical_abstract.png`, generated by `generate_graphical_abstract()` — the paper's graphical abstract for the PDF cover and HTML page (v2: tall 9.6 x 11.8 in portrait layout, full-word stance counts, no letter codes). It carries no `{#fig:...}` label, is not in the figure registry, and is not counted among the eleven registered figures.

Incident-lesson taxonomy: the incident figure places each of the 14 incidents in one of five lesson classes (`containment_held`, `authority_exceeded`, `supply_chain`, `update_operations`, `cognitive_boundary` — pinned in `evidence.LESSON_TAXONOMY`); `update_operations` is deliberately empty in the current 14-incident mapping.

## Data artifacts — 10 in `output/data/` (plus the variables file)

| Artifact | Content | Rows/shape |
|---|---|---|
| `evaluation_matrix.csv` | Candidate × property stances: `candidate_id, candidate_name, property_id, stance` | 216 rows (24 candidates × 9 properties), 100% coverage |
| `scenario_recommendations.csv` | One recommendation per scenario: `scenario_id, situation, recommendation, change_condition` | 8 rows |
| `evidence_summary.json` | Source-tier counts (official / advisory / incident_report / research / community) + the capability baseline constants | single object |
| `incident_register.csv` | The 14 documented incidents: `incident_id, date, actor_class, vector, boundary_lesson, lesson_class, citation` | 14 rows |
| `candidate_basis.csv` | One stance-profile basis per candidate: `basis_id, summary, primary_sources` (semicolon-joined bib keys) | 24 rows (from `basis.CANDIDATE_BASIS`) |
| `defensive_stack.csv` | Candidate × mitigation-class stances: `candidate_id, class_id, stance` | 192 rows (24 candidates × 8 mitigation classes) |
| `update_windows.csv` | Documented support/update policies: `candidate_id, policy, months` | 24 rows |
| `os_stack_coverage.csv` | Archetype x layer stances over the eight-layer OS security stack: `archetype_id, archetype, layer_id, layer, stance` | 64 rows (8 category archetypes x 8 stack layers) |
| `formal_definitions.json` | The eight pinned formal definitions: `definition_id, name, formal_latex, informal, surface, citation_keys` | 8 definitions (from `formal.FORMAL_DEFINITIONS`) |

## Reports — `output/reports/`

Human-readable run summaries (analysis run metadata, artifact hashes, `build_clock.py` timestamps honoring `SOURCE_DATE_EPOCH`).

## Regeneration commands

```bash
uv run python scripts/10_evaluation_analysis.py          # 11 figures + cover graphical abstract + 10 data artifacts + validation report
uv run python scripts/z_generate_manuscript_variables.py # manuscript_variables.json (+ template injection when detected)
```

If any artifact is missing, stale, or non-deterministic, do not patch it — fix the generator in `src/` and regenerate.
