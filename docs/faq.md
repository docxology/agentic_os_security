# faq.md

**Q: Is this published? Where's the DOI?**
There is no DOI, no Zenodo deposit, no public metadata. The project is **private** by design; no publishing actions happen without the owner's explicit ask. `CITATION.cff` and `codemeta.json` record identity for internal use only.

**Q: Are the OS assessments based on penetration testing?**
No. Every assessment is an analytical judgment from documented designs, official documentation, advisories, and published incident reports. The project performs no offensive work and assigns no numeric security scores — stances are qualitative (`strong | partial | weak | n_a`).

**Q: Can I add a source mid-project?**
Add the entry to `manuscript/references.bib` and a matching `Source` in `src/agentic_os_security/evidence.py` with a tier (`official | advisory | incident_report | research | community`). Tests enforce key parity between the two; the canonical count is 155 source-derived + 13 scholarly = 168 keys, so extending it is a deliberate contract change, not a drive-by.

**Q: Why no mermaid diagrams in the manuscript?**
The render pipeline runs from the sibling template repo and this project keeps it free of diagram-tool prerequisites. Diagram-shaped content lives in the registered PNG figures (11 of them, plus the cover graphical abstract) generated by `src/agentic_os_security/figures/`. Mermaid is fine in `docs/` and root docs.

**Q: Why does `output/` regenerate instead of being edited?**
All artifacts are deterministic outputs of `src/` + config. Hand edits would be silently overwritten and would break the byte-reproducibility guarantee. Fix the generator, rerun `uv run python scripts/10_evaluation_analysis.py`.

**Q: What are the `{{TOKENS}}` in the manuscript and where do they come from?**
They are resolved by `src/agentic_os_security/manuscript_variables.py::generate_variables()` and written to `output/data/manuscript_variables.json` by `scripts/z_generate_manuscript_variables.py`. Only tokens from the plan in `docs/syntax_guide.md` may appear; tests fail on unresolved or invented tokens.

**Q: What are the two failure paths?**
**Exploitation** — an agent leverages a kernel or implementation flaw to escape containment. **Authorized misuse** — an agent with legitimate credentials and tool access abuses them; no exploit needed. The second path motivates the trust-domain/controls/invariants architecture in sections 09 and 13.

**Q: What is the forecast horizon and how confident are the forecasts?**
2028–2031, with explicit confidence tiers (`high | moderate | low`) computed in `src/agentic_os_security/forecasts.py` and surfaced via `{{RESULT_FORECAST_*}}` tokens. Forecasts are clearly distinguished from measurements in the prose.

**Q: Where does the timestamp in artifacts come from?**
`src/agentic_os_security/build_clock.py`, which honors `SOURCE_DATE_EPOCH` and falls back to the review date (2026-09-10, noon UTC). Wall-clock never touches generated artifacts.
