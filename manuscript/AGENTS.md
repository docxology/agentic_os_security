## RASP + attribution conventions

- No "In summary"/"In conclusion" closers; active voice; concrete paths; one idea per paragraph; no filler.
- Analytical judgments from documented designs — never implied penetration testing; vendor findings labeled as vendor findings; forecasts distinguished from measurements; **no numeric security scores**.
- Citations only `[@key]` with keys from `references.bib`; cross-refs only `[@sec:...]`/`[@fig:...]`/`[@tbl:...]`/`[@eq:...]`/`[@def:...]`/`[@rem:...]`; every H1 carries its pinned `{#sec:...}` label.
- **No mermaid fences** in any `manuscript/*.md` (render prerequisite is deliberately zero diagram tooling).

## Equation protocol (v0.4.0)

- Formal statements are display-math blocks `$$ ... $$ {#eq:<label>}` referenced as `[@eq:<label>]`; the eight-label registry with statements and section homes is in [`SYNTAX.md`](SYNTAX.md).
- Each registered label is defined exactly once across the numbered sections (enforced by `tests/test_manuscript_structure.py`); keep the LaTeX renderable — no unicode math, `\textit` allowed.

## Definition-block protocol (v0.5.0)

- Formal concepts are auto-numbered fenced blocks `:::: {.definition #def:<label> title="..."}` closed with `::::`; the block may wrap its display equation, which keeps its own `{#eq:...}` label inside the block (syntax + the 8-block registry with titles and section homes are in [`SYNTAX.md`](SYNTAX.md)).
- Reference concepts as `[@def:<label>]`; the `formalism.lua` filter numbers and resolves them (never natbib). Never hand-number a Definition; counters run in document order across sections 03, 07, 09, 12, 13.
- Every registered def label is declared exactly once across the numbered sections and every `[@def:...]` target is registered (enforced by `tests/test_manuscript_structure.py`); every registered eq label keeps at least one `[@eq:...]` inline reference or is absorbed by its Definition block.

## Remark-block protocol (v0.6.0)

- Analytical observations that are not definitions are auto-numbered fenced blocks `:::: {.remark #rem:<label> title="..."}` closed with `::::` (syntax + the 2-block registry with titles and section homes are in [`SYNTAX.md`](SYNTAX.md)); one plain-prose paragraph per block, no display math.
- Reference remarks as `[@rem:<label>]`; the `formalism.lua` filter numbers and resolves them (never natbib). Never hand-number a Remark; remarks get their own counter (Remark 1, 2, …) — definitions continue 1–8 in document order across sections 03, 07, 09, 12, 13.
- Every registered remark label is declared exactly once across the numbered sections and every `[@rem:...]` target is registered (enforced by `tests/test_manuscript_structure.py` via `REMARK_LABELS`).

## Section modification workflow

1. Edit the section source (`NN_name.md`) — respecting the H1/label and conventions above.
2. If prose references new numbers: register them in `data/claim_ledger.yaml`; if they come from code, update the registry module, not the prose constant.
3. Regenerate: `uv run python scripts/10_evaluation_analysis.py` (if registry/figure content changed), then `uv run python scripts/z_generate_manuscript_variables.py`.
4. Verify locally: `uv run pytest tests/ --cov=src --cov-fail-under=90` (structure, token, parity tests run against the real files).
5. Render **from the template repo** (`projects/working/` link): `uv run python scripts/pipeline/stage_03_render.py --project working/agentic_os_security`.

Never edit the resolved/hydrated tree in the template environment; it is generated.
